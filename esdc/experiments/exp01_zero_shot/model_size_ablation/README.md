# exp01_zero_shot — Model-Size Ablation

## What this ablation tests

All other ESDC experiments use the ViT-Ti architecture fixed in
`esdc/experiments/shared_config.yaml` (embed_dim=192, depth=12, num_heads=3).
This ablation asks how much zero-shot gap-filling performance depends on
model capacity, by pre-training the same `exp01_zero_shot` pipeline at 6
progressively smaller architectures and comparing zero-shot MAE on the same
canonical eval set:

| Variant | embed_dim | depth | num_heads | Params |
|---|---|---|---|---|
| (baseline, reused — see below) | 192 | 12 | 3 | 11,105,488 |
| 192_12_2 | 192 | 12 | 2 | 9,925,840 |
| 192_6_2  | 192 | 6  | 2 | 5,184,208 |
| 96_6_2   | 96  | 6  | 2 | 1,661,296 |
| 96_6_1   | 96  | 6  | 1 | 1,366,384 |
| 96_3_1   | 96  | 3  | 1 | 770,800 |
| 48_3_1   | 48  | 3  | 1 | 263,296 |

(Param counts are recorded by `evaluate_gapfilling.py` in each
`results/<label>/run_info.json` — see `results/RESULTS.md`.)

Variant labels follow the `{embed_dim}_{depth}_{num_heads}` convention.

**The (192,12,3) baseline is not retrained.** It's architecturally identical
to `exp01_zero_shot`'s own default model, which already has a trained
checkpoint and tracked results (`../results/`). This ablation reuses those
directly as the largest data point, following the same convention
used by `max_gap_ablation` (references `exp01_zero_shot`'s results rather
than retraining an identical config).

Each of the 6 variants is an **independent from-scratch pre-training
run** (`type: zero_shot`, same as `exp01_zero_shot` itself), using the exact
same pre-training LMDB, `base_lr`, `warmup_steps`, and DDP degree (4 GPUs) as
`exp01_zero_shot` — only `model.embed_dim/depth/num_heads` and
`training.log_dir` differ per variant. No other hyperparameter needs
adjusting: unlike `exp02_finetuning/sample_ablation` (which shrinks the
*dataset*, requiring LR/warmup/DDP-degree special-casing at small sample
counts), this ablation trains on the full pre-training LMDB at every variant,
so those concerns don't apply. All `embed_dim/num_heads` pairs tested divide
evenly (no attention-head compatibility issue).

Each checkpoint is evaluated zero-shot (`gap_only_masking=True`, no
fine-tuning) on the same canonical eval set as every other experiment
(`$ESDC_GAP_FILLING_DIR/dataset.h5`).

**This is purely an ablation.** It does not change `exp01_zero_shot` itself —
`../config.yaml` and `../scripts/` are untouched.

## Directory layout / how to run

```
model_size_ablation/
├── configs/{192_12_2,192_6_2,96_6_2,96_6_1,96_3_1,48_3_1}.yaml   — one config per variant
├── results/{<label>}/            — metrics.json + run_info.json
├── results/RESULTS.md            — generated by collect_results.py
├── results/loss_vs_model_size.png — generated by plot_results.py
└── scripts/
    ├── local/{train,evaluate}.sh              — CPU sanity check, all 6 variants, real (unshrunk) architectures
    ├── slurm/train_all.sh                     — real GPU run, all 6 variants as sequential job steps in ONE allocation
    ├── slurm/evaluate_all.sh                  — real GPU eval, all 6 variants as sequential job steps in ONE allocation
    ├── slurm/{train,evaluate}_<label>.sh      — one-variant-per-job scripts, for re-running a single variant in isolation
    ├── collect_results.py                     — aggregates results/<label>/ + exp01_zero_shot reference → RESULTS.md
    └── plot_results.py                        — plots MAE (K) vs. parameter count → loss_vs_model_size.png
```

**Local** (from the project root, `conda activate gap-aware`):
```bash
bash esdc/experiments/exp01_zero_shot/model_size_ablation/scripts/local/train.sh
bash esdc/experiments/exp01_zero_shot/model_size_ablation/scripts/local/evaluate.sh
```
CPU, `--max_epochs 2 --max_samples 100`, for all 6 variants — this only
proves each of the 6 distinct architectures trains/evaluates without error.
Unlike other ablations' local scripts, this one does **not** override
`--embed_dim/--depth/--num_heads` to a trivial size, since architecture is
exactly what's under test here. Local evaluation doesn't write tracked
results (matches every other experiment's local sanity-check convention).

**HPC**:
```bash
sbatch esdc/experiments/exp01_zero_shot/model_size_ablation/scripts/slurm/train_all.sh
# once it finishes:
sbatch esdc/experiments/exp01_zero_shot/model_size_ablation/scripts/slurm/evaluate_all.sh
```
Both submit a single job that trains/evaluates all 6 variants as sequential
job steps within one resource allocation, avoiding repeated GPU-allocation
queueing. Per-variant `train_<label>.sh`/`evaluate_<label>.sh` scripts are
also provided for re-running a single variant in isolation.
