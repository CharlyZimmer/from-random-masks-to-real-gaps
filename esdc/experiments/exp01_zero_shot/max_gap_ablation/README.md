# exp01_zero_shot — Max-Gap-Ratio Ablation

## What this ablation tests

All ESDC datasets are built with `max_gap_portion=0.2` at
dataset-creation time (`create_esdc_dataset.py`): patches whose raw target has
more than 20% NaN are discarded, everything up to that threshold is kept. This
ablation asks how much that threshold matters for `exp01_zero_shot`'s
zero-shot gap-filling performance, by testing two stricter thresholds:
**0% (only fully gap-free targets)** and **10%**.

Unlike the dataset-creation-time knob, this ablation does **not** create a new
dataset. It **post-hoc filters the already-existing pre-training LMDB**
(`$ESDC_DATA_DIR/lmdb/dataset.lmdb` / `dataset_test.lmdb` — the exact same LMDB
`exp01_zero_shot` itself trains on) at training time, via the
`max_gap_ratio` parameter on `ConsecutiveLMDBDataset`/`LMDBConsecutiveDataModule`
(`model_gap_aware/lmdb_training.py`). For each sample, the middle input frame's
primary-variable (LST, channel 0) NaN ratio is computed once at dataset
construction, and samples above the threshold are dropped before the
train/val split. This is only *exactly* equivalent to the original
creation-time `max_gap_portion` filter because the pre-training dataset is
built **without** `--syn_gaps` — its `y_train`/`X_train` middle frame is the
untouched raw target, so nothing about the original filter criterion is lost
by writing it to disk first and filtering later. (The gap-filling *training*
dataset, by contrast, has synthetic donor gaps baked into every frame before
being written, which destroys the natural-gap information needed for this —
that dataset is out of scope here, and isn't touched by `exp01_zero_shot`'s
own pipeline anyway.)

Each variant is an **independent from-scratch pre-training run** (`type:
zero_shot`, same as `exp01_zero_shot` itself) — not a fine-tune of an existing
checkpoint (unlike `exp02_finetuning/sample_ablation/`). Architecture and all
other hyperparameters are identical to `exp01_zero_shot`'s own `config.yaml`/
`shared_config.yaml` (embed_dim=192, depth=12, num_heads=3, patch_size=4, 50
epochs, `gap_only_masking=false`) — only `data.max_gap_ratio` and
`training.log_dir` differ per variant. Each checkpoint is then evaluated
zero-shot (`gap_only_masking=True`, no fine-tuning) on the same canonical eval
set as every other experiment (`$ESDC_GAP_FILLING_DIR/dataset.h5`).

**This is purely an ablation.** It does not change `exp01_zero_shot` itself —
`../config.yaml` and `../scripts/` are untouched.

## Sample counts after filtering

On the full HPC pre-training LMDB, the filter keeps 20,279 (gap000) and
79,025 (gap010) of the 109,339 samples used by the unfiltered
`exp01_zero_shot` (train + val, recorded as `num_finetuning_samples` in each
`results/*/run_info.json`). The training script prints a `kept N/M samples`
line for each run.

For reference, the counts on the local pre-training LMDB
(`esdc/data/lst_no_syn_gaps/lmdb/`, a small 2003-01-01→2003-05-01 subset, 4276 train / 1062 test samples total,
built with the unfiltered `max_gap_portion=0.2`):

| Variant | max_gap_ratio | Train kept | Test kept |
|---|---|---|---|
| gap000 | 0.0 | 1039 / 4276 (24.3%) | 277 / 1062 (26.1%) |
| gap010 | 0.1 | 3193 / 4276 (74.7%) | 794 / 1062 (74.8%) |

Both comfortably exceed the local sanity-check scale (`--max_samples 100`).

## Directory layout / how to run

```
max_gap_ablation/
├── configs/{gap000,gap010}.yaml        — one config per variant
├── results/{gap000,gap010}/            — metrics.json + run_info.json
├── results/RESULTS.md                  — generated by collect_results.py
└── scripts/
    ├── local/{train,evaluate}.sh       — CPU sanity check, both variants, tiny model
    ├── slurm/{train,evaluate}_{gap000,gap010}.sh  — real GPU runs, one script per variant/op
    └── collect_results.py              — aggregates results/{gap000,gap010}/ + exp01_zero_shot reference → RESULTS.md
```

**Local** (from the project root, `conda activate gap-aware`):
```bash
bash esdc/experiments/exp01_zero_shot/max_gap_ablation/scripts/local/train.sh
bash esdc/experiments/exp01_zero_shot/max_gap_ablation/scripts/local/evaluate.sh
```
CPU, tiny model, `--max_epochs 2 --max_samples 100` for both variants — this
only proves the two differently-filtered variants train/evaluate without
error. Local evaluation doesn't write tracked results (matches every other
experiment's local sanity-check convention).

**HPC**:
```bash
sbatch esdc/experiments/exp01_zero_shot/max_gap_ablation/scripts/slurm/train_gap000.sh
sbatch esdc/experiments/exp01_zero_shot/max_gap_ablation/scripts/slurm/train_gap010.sh
# once each finishes:
sbatch esdc/experiments/exp01_zero_shot/max_gap_ablation/scripts/slurm/evaluate_gap000.sh
sbatch esdc/experiments/exp01_zero_shot/max_gap_ablation/scripts/slurm/evaluate_gap010.sh
```
