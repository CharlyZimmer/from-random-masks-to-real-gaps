# exp02_finetuning — Sample-Count Ablation

## What this ablation tests

This ablation measures how much fine-tuning data the `exp01_zero_shot`
checkpoint needs for gap-filling. Fine-tuning only has to learn a small
correction on top of an already-converged encoder, so a small number of
samples may be enough.

The sample counts follow a doubling series (**50, 100, 200, 400, 800, 1600,
3200, 6400, 12800**), which spaces the points evenly on a log-x axis. Each
variant fine-tunes a separate copy of the `exp01_zero_shot` checkpoint on N
samples from the test split of the gap-filling training LMDB. The subset is
drawn with the same seeded `random_split(seed=42)` subsetting that
`exp02_finetuning` uses (see `model_gap_aware/lmdb_training.py`). Every variant
trains for **20 epochs** and is evaluated on the same canonical eval set as
every other experiment (`$ESDC_GAP_FILLING_DIR/dataset.h5`).

`exp02_finetuning` itself uses N=100 with the same settings as
`configs/n0100.yaml` (see `../config.yaml`).

## Method — what's identical / different across variants

Identical across all 9 variants: pretrained source (`exp01_zero_shot`'s best
checkpoint, auto-discovered), model architecture (`embed_dim=192, depth=12,
num_heads=3, decoder_heads=1, patch_size=4`), effective peak fine-tuning LR
(4e-5), `max_epochs=20`, training/eval LMDBs and eval dataset,
`gap_only_masking=True`.

Different: `max_samples` capped per variant, `warmup_steps` computed per
variant (see below), separate `training.log_dir` per variant so all 9
checkpoints coexist under `esdc/lightning_logs/`.

**n0050/n0100/n0200 additionally differ in `devices`/`base_lr`** from
n0400-n12800. At N=50, 4-way DDP (`shared_config.yaml`'s default) gives
`steps_per_epoch = (n_train=48 // 4) // batch_size=16 = 0`, i.e. zero
training steps, and N=100/200 are not much better (1-2 steps/epoch). These 3
configs use `devices: 1` instead. Since `run_training.py` computes
`lr = base_lr * n_devices`, dropping from 4 devices to 1 would also quarter
the peak LR. These 3 configs therefore set `base_lr: 4.0e-5` (vs. `1.0e-5` for
n0400-n12800), so the actual peak LR is 4e-5 for all 9 variants and sample
count stays the only independent variable.

## Warmup schedule

Each variant warms up for about one epoch, so that the LR ramp does not
perturb the already-converged pretrained checkpoint. A fixed percentage of
total steps would not keep this meaning across very different dataset sizes.
The warmup is computed per variant from
`gap_aware_training.py`'s own `total_steps` formula
(`n_train = N - max(1, int(0.05*N))`, `steps_per_epoch = (n_train // devices) // 16`,
`total_steps = steps_per_epoch * 20`), floored at 10 steps to avoid a
degenerately short ramp at the smallest N:

| Label | N | devices | n_train | steps/epoch | total_steps (20 ep) | warmup_steps | warmup % of total |
|---|---|---|---|---|---|---|---|
| n0050 | 50 | 1 | 48 | 3 | 60 | 10 (floored) | 16.7% |
| n0100 | 100 | 1 | 95 | 5 | 100 | 10 (floored) | 10.0% |
| n0200 | 200 | 1 | 190 | 11 | 220 | 11 | 5.0% |
| n0400 | 400 | 4 | 380 | 5 | 100 | 10 (floored) | 10.0% |
| n0800 | 800 | 4 | 760 | 11 | 220 | 11 | 5.0% |
| n1600 | 1600 | 4 | 1520 | 23 | 460 | 23 | 5.0% |
| n3200 | 3200 | 4 | 3040 | 47 | 940 | 47 | 5.0% |
| n6400 | 6400 | 4 | 6080 | 95 | 1900 | 95 | 5.0% |
| n12800 | 12800 | 4 | 12160 | 190 | 3800 | 190 | 5.0% |

## Directory layout / how to run

```
sample_ablation/
├── configs/n{0050,0100,0200,0400,0800,1600,3200,6400,12800}.yaml   — one config per variant
├── results/n{0050,0100,0200,0400,0800,1600,3200,6400,12800}/       — metrics.json + run_info.json
├── results/RESULTS.md, loss_vs_samples.png                  — generated by the scripts below
└── scripts/
    ├── local/{train,evaluate}.sh                — CPU sanity check, all 9 variants, tiny model
    ├── slurm/train_all.sh, evaluate_all.sh       — n0400-n12800 fine-tuning (4-GPU) / all 9 evaluations (1-GPU), sequential steps in one job allocation each
    ├── slurm/train_small_all.sh                  — n0050/n0100/n0200 fine-tuning (1-GPU), sequential steps in one job allocation
    ├── slurm/train_n*.sh, evaluate_n*.sh         — real GPU runs, one script per variant
    ├── collect_results.py                        — aggregates results/n*/ + exp02/exp04 references → RESULTS.md
    └── plot_results.py                           — eval MAE vs. N samples plot
```

**Local** (from the project root, `conda activate gap-aware`):
```bash
bash esdc/experiments/exp02_finetuning/sample_ablation/scripts/local/train.sh
bash esdc/experiments/exp02_finetuning/sample_ablation/scripts/local/evaluate.sh
```
CPU, tiny model, `--max_samples 100 --max_epochs 2` for every variant — this
only proves the 9 differently-configured variants train/evaluate without
error. The local gap-filling-training LMDB has only 806 entries total, so the
real target sample counts (≥800) aren't reachable locally; meaningful numbers
only come from the HPC runs below. Local evaluation doesn't write tracked
results (matches every other experiment's local sanity-check convention).

**HPC**.
`n0400-n12800` need a 4-GPU allocation (DDP); `n0050/n0100/n0200` need only 1
GPU (see "Method" above) — so they're two separate combined jobs. Evaluation
is always 1-GPU and covers all 9 in one job:
```bash
sbatch esdc/experiments/exp02_finetuning/sample_ablation/scripts/slurm/train_all.sh        # n0400-n12800, 4 GPUs
sbatch esdc/experiments/exp02_finetuning/sample_ablation/scripts/slurm/train_small_all.sh   # n0050/n0100/n0200, 1 GPU
# once both finish:
sbatch esdc/experiments/exp02_finetuning/sample_ablation/scripts/slurm/evaluate_all.sh      # all 9, 1 GPU
```
The individual `train_n*.sh`/`evaluate_n*.sh` scripts re-run a single
variant in isolation (e.g. after a mid-sweep failure) without resubmitting a
whole `*_all.sh` job.

`--time` budgets are rough linear estimates based on each variant's number of
training steps.
